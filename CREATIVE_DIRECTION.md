# Creative Direction

## Thesis

The portfolio is an interactive visualization of divergence, emergence, instability, and convergence.

A tiny difference in initial conditions grows into complexity. Complexity eventually separates into two stable outcomes. Those outcomes become the two featured projects.

The visitor should initially think:

> What am I looking at?

and only later realize:

> This system is the portfolio.

## Narrative arc

1. Void
2. Seed
3. Near-identical trajectories
4. Divergence
5. Multiplication
6. Emergent field
7. Instability
8. Bifurcation
9. Two project attractors
10. Commitment to a project world
11. Decomposition back into the parent system

The project UI must be born from the visual system instead of appearing on top of it.

## Emotional qualities

- dark
- minimal
- cinematic
- mathematical
- mysterious
- precise
- experimental
- technically credible
- restrained rather than flashy

## What makes the experience memorable

The simulation is not a background. It is the navigation, transition language, and conceptual metaphor.

A viewer should be able to recognize the site from a five-second screen recording with all copy removed.

## Anti-patterns

Do not introduce:

- standard portfolio hero sections
- conventional project cards
- glass panels
- gradient blobs
- feature grids
- skill badges
- generic scroll reveals
- decorative 3D objects without conceptual purpose
- terminal cosplay
- excessive fake scientific labels
- gratuitous camera spinning

## Typography

Three roles:

1. Display — severe editorial typography for names and project titles.
2. Interface — clean neutral sans-serif for navigation and metadata.
3. System — restrained monospace for telemetry and mathematical annotations.

The system layer should feel like instrumentation, not a hacker terminal.

## Color

Start near-monochrome.

- background: near-black graphite
- primary text: warm off-white
- secondary text: muted gray
- simulation: white / silver

Project-specific color may enter only when the two attractors become distinct. Color should behave like a property of the worlds, not a site-wide gradient.

## Content rule

Technical depth must match visual ambition. Project worlds should reveal architecture, decisions, failure modes, tradeoffs, metrics, and outcomes rather than hiding behind spectacle.
